# Компоненты прошивки

Каждый модуль прошивки — отдельный компонент ESP-IDF в своей папке
(`components/wcs_<имя>/`) с публичным заголовком в `include/` и явными
зависимостями в `REQUIRES` / `PRIV_REQUIRES`. `main` только собирает их вместе.

Компоненты этапа 1 (по ТЗ, раздел «Модули прошивки»):

| Компонент | Назначение | Статус |
| --- | --- | --- |
| `wcs_defaults` | заводские настройки, генерируются из `firmware/.env` | есть |
| `wcs_button` | кнопка: подавление дребезга, события «клик», 5 с, 15 с | есть |
| `wcs_wifi` | точка доступа WPA2/WPA3, клиент Wi-Fi с переподключением, поиск сетей | есть (без таймера выключения) |
| `wcs_auth` | PBKDF2-хэш пароля, сессии, защита от перебора | есть (пароль пока только заводской) |
| `wcs_web` | веб-сервер: вход; в «Настройке» — мастер выбора режима, в Direct — консоль. Маршруты — таблицы `web_route_t` с уровнем доступа (вход проверяется в одном месте). Файлы из `www/pages/` и `www/assets/` встраиваются генератором `gen_www.py`, крупные тексты сжимаются gzip | есть, HTTPS |
| `wcs_storage` | настройки в NVS: режим, Wi-Fi для бастиона, адрес бастиона, SSID и пароль точки Direct, параметры консольного порта | есть |
| `wcs_tls` | ключ ECDSA P-256 и самоподписанный сертификат HTTPS: создаются при первом запуске, хранятся в NVS (`wcs_tls`), сброс до заводских их не стирает | есть |
| `wcs_bastion` | адрес бастиона (порт по умолчанию 7443), поиск имени (DNS / mDNS `.local`), проверка: TLS 1.3, корневой сертификат и код бастиона | есть |
| `wcs_link` | WCS Link (`docs/protocol.md`): ключ устройства и его код, заявка, сертификат, mTLS, heartbeat, время от бастиона, переподключение; консоль (вывод — кадры `0x01` из буфера 16 КиБ в PSRAM, ввод — `0x02` с кредитом), команды бастиона (`console_config`, `console_break`, `wifi_config`, `reboot`, `revoke`), `status` | есть |
| `wcs_console` | UART консоли (пины и скорость по умолчанию — из `board.h`), параметры линии с сохранением в NVS, BREAK (инверсия TX), история вывода в PSRAM (`CONFIG_WCS_CONSOLE_HISTORY_KB`), подписчики на вывод | есть |
| `wcs_fsm` | машина состояний: «Заводское», «Настройка», Direct, Bastion; своя задача, переходы по командам из очереди; тайминги кнопки и точки доступа — в Kconfig; `wcs_fsm_get_state()` для других модулей | есть |
| `wcs_led` | RGB-светодиод: цвет, характер свечения, слои (`docs/led.md`) | есть |

Связь между компонентами — через публичные API и события `esp_event`
(например, `WCS_BUTTON_EVENT`). Настраиваемые параметры компонента — в его `Kconfig`
(`idf.py menuconfig` → «ESP WCS: …»).

Как добавить в веб-интерфейс:

- **страницу** — файл в `wcs_web/www/pages/` и маршрут с `.access = WEB_ACCESS_PAGE`,
  обработчик — `web_send_file(req, "pages/<имя>.html")`;
- **скрипт, стиль, картинку** — файл в `wcs_web/www/assets/`, доступен по `/assets/<имя>`
  сам, CMake править не нужно (незнакомый тип файла — добавить в `TYPES` в `gen_www.py`);
- **API** — маршрут в таблице режима (`web_setup.c` / `web_direct.c`). Поле `.access`
  можно не указывать: по умолчанию нужен вход. `WEB_ACCESS_PUBLIC` — только осознанно.

Правила:

- пины и параметры железа берутся только из `main/board.h` (передаются в компоненты через конфигурацию при инициализации);
- компонентам, использующим PSRAM, — `esp_psram` в `PRIV_REQUIRES`;
- драйверы указывать явно (`esp_driver_uart`, `esp_driver_gpio`, …).

## Консоль в Direct (`/console`, `/ws/console`)

Страница — xterm.js из `wcs_web/www/assets/xterm/` (та же версия, что у бастиона:
`@xterm/xterm` 6.0.0, `@xterm/addon-fit` 0.11.0; обновлять вместе с `bastion/assets/vendor/xterm`).

WebSocket `wss://192.168.4.1/ws/console`. Вход и `Origin` проверяются до рукопожатия
(`ws_pre_handshake_cb`); каждый кадр продлевает сессию администратора, страница шлёт
`ping` раз в минуту — открытая консоль не разлогинивает.

| Направление | Кадр | Значение |
| --- | --- | --- |
| браузер → ESP | бинарный | ввод в UART (только у владельца консоли) |
| ESP → браузер | бинарный | вывод UART; после получения консоли — сначала история |
| браузер → ESP | `{"t":"hello"}` | занять консоль, если она свободна |
| браузер → ESP | `{"t":"take"}` | забрать консоль у другого |
| браузер → ESP | `{"t":"line","baud":115200,"data_bits":8,"parity":"none","stop_bits":1}` | параметры порта (сохраняются) |
| браузер → ESP | `{"t":"break"}` | BREAK |
| браузер → ESP | `{"t":"ping"}` | продлить сессию (ответ `pong`) |
| ESP → браузер | `{"t":"state","owner":true,"line":{…}}` | консоль ваша, текущие параметры порта |
| ESP → браузер | `{"t":"busy"}` / `{"t":"taken"}` | консоль занята / её забрали |
| ESP → браузер | `{"t":"error","error":"invalid_line"}` | команда не выполнена |
| ESP → браузер | `{"t":"logout"}` | сессия закончилась, соединение закрывается |

Управляет консолью один клиент. Остальные видят «Устройство занято» и кнопку «Забрать».
Если браузер не успевает забирать вывод, больше 32 КиБ в очереди не копится — лишнее
отбрасывается (в логе ESP предупреждение).

Проверка без коммутатора: перемычка GPIO17 ↔ GPIO18 (J1-10 ↔ J1-11) — всё набранное
возвращается эхом.

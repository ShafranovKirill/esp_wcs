# Бастион: сотрудники, права, карты

Проект следующего шага бастиона. Сейчас — один администратор и папки в один уровень
([`bastion.md`](bastion.md)). Здесь — несколько сотрудников, дерево папок, права на
узлы дерева (RBAC) и карты устройств на папках.

Решения согласованы, реализации ещё нет. План — [`roadmap.md`](roadmap.md), раздел
«Сотрудники, права, карты».

## Пример

```
Здание А                      ← «Сетевики А» — Оператор
├── Этаж 1                       (видят и работают со всем внутри)
│   ├── Кабинет 101
│   └── Кабинет 102
└── Этаж 3                    ← Петров — Инженер
    └── Серверная 301            (Wi-Fi и перезагрузка — только здесь)
Ядро сети                     ← Сидоров — Наблюдатель
```

Коммутатор из серверной 301 можно положить и в «Ядро сети»: Сидоров увидит его оттуда,
не получая доступа ко всему зданию.

## Дерево папок

| Правило | Значение |
| --- | --- |
| Вложенность | любая, до 8 уровней |
| Хранение | материализованный путь — ID папок от корня через `/` (`<id А>/<id Этаж 3>/<id 301>`); «всё внутри» — `path LIKE '<путь>/%'` по индексу `text_pattern_ops` |
| Имя | 1–64 символа, уникально среди соседей без учёта регистра |
| Перенос папки | вместе с содержимым, одной транзакцией (пересчёт путей поддерева); нельзя внутрь себя |
| Удаление | только пустой папки (без подпапок и устройств) |
| Устройство | в одной или нескольких папках; без папок — «Без папки» |

**Устройство в нескольких папках.** Папка — не место хранения, а набор, как метка.
Коммутатор может одновременно лежать в «Здание А / Этаж 3 / Серверная 301» и в
«Ядро сети». Доступ к нему — объединение прав по всем его папкам. Поэтому добавить
устройство в папку может только тот, у кого есть `device.configure` на устройство
**и** `folder.manage` на папку: иначе любой открыл бы своё устройство чужой группе
или получил бы доступ к чужому, положив его к себе.

Новые заявки и одобренные устройства без папки видят только сотрудники с глобальными
правами.

## Сотрудники и группы

| Правило | Значение |
| --- | --- |
| Вход | только логин и пароль (Argon2), без LDAP и второго фактора |
| Логин | 1–64 символа: буквы, цифры, `. _ -`; уникален без учёта регистра |
| Пароль | не короче 12 символов и не из шаблона (как сейчас у администратора) |
| Свой пароль | сотрудник меняет сам, с вводом текущего |
| Администратор сотрудников | создаёт, блокирует, сбрасывает пароль (новый пароль показывается один раз) |
| Блокировка, сброс пароля | все сессии сотрудника закрываются сразу, открытая консоль освобождается |
| Защита от перебора | как сейчас: после 5 неверных паролей — нарастающая пауза, по логину и по IP |
| Первый сотрудник | из `bastion/.env` через `mix bastion.admin`, роль «Суперадмин»; удалить или лишить роли последнего суперадмина нельзя |

**Группа** — набор сотрудников («Сетевики А»). Права выдаются человеку лично или
группе; итог для человека — объединение того и другого. Новичка добавляют в группу —
и у него права отдела; ушёл из отдела — убрали из группы, права пропали.

## Роли и права

**Роль** — именованный набор действий. **Выдача** — тройка «кому (сотрудник или
группа) + роль + папка». Роль одна на всех («Оператор»), меняется только папка.

| Действие | Что даёт |
| --- | --- |
| `view` | видеть устройство, статус, сведения, журнал, карту папки |
| `console.read` | смотреть консоль без ввода |
| `console.write` | ввод, «Забрать консоль», BREAK |
| `device.configure` | параметры порта, имя, папки устройства |
| `device.wifi` | смена Wi-Fi |
| `device.reboot` | перезагрузка |
| `device.revoke` | отзыв и удаление |
| `folder.manage` | создавать, переименовывать, переносить и удалять подпапки; редактировать карту |

Глобальные действия — выдаются без папки:

| Действие | Что даёт |
| --- | --- |
| `enrollment.approve` | заявки: одобрить, отклонить, положить в папку |
| `users.manage` | сотрудники, группы, выдачи |
| `roles.manage` | создание и изменение ролей |
| `superadmin` | всё, включая устройства «Без папки» |

Правила:

- **Права наследуются вниз.** Выдача на «Здание А» действует на все этажи и кабинеты внутри.
- **Только разрешения, без запретов.** Итог — объединение всех выдач.
- Действия зависят друг от друга: `console.write` включает `console.read`, любое действие
  включает `view`. Редактор ролей ставит зависимые галочки сам.
- Папки, на которые нет прав, в дереве не видны. Родительские папки показываются
  серыми, только как путь до доступной: «Здание А» серым, внутри — доступный «Этаж 3».

Заводские роли (можно менять, кроме «Суперадмина»):

| Роль | Действия |
| --- | --- |
| Наблюдатель | `view`, `console.read` |
| Оператор | Наблюдатель + `console.write` |
| Инженер | Оператор + `device.configure`, `device.wifi`, `device.reboot`, `folder.manage` |
| Суперадмин | `superadmin` |

### Проверка прав

- Права проверяются **внутри контекстов**, а не только скрытыми кнопками: функции
  `Fleet`, `Console`, `Control`, `Maps` получают первым аргументом `actor` и возвращают
  `{:error, :forbidden}`. Событие LiveView без права отклоняется так же.
- `Access.can?(actor, action, device_or_folder)` — пути всех папок устройства против
  путей выдач сотрудника и его групп. Набор выдач сотрудника кешируется в процессе
  LiveView и сбрасывается событием `Access.GrantsChanged`.
- Отобрали право — открытые страницы пересчитываются сразу: консоль освобождается и
  отключается, страница устройства без `view` закрывается.
- Списки фильтруются в запросе к БД (по префиксу пути), а не после выборки.

### Консоль

- Владеть консолью и вводить может только сотрудник с `console.write`; «Забрать» —
  тоже только он.
- С `console.read` консоль видна без ввода: сейчас вывод получает только владелец,
  читатели подпишутся на ту же тему `console:<id>`.

### Журнал

В каждом событии — кто его вызвал (сотрудник, а не «администратор»). Отдельный журнал
доступа: вход, неудачный вход, блокировка, смена пароля, изменения ролей, групп и выдач.

## Карта папки

У папки вкладка **«Карта»**: подложка (план этажа, схема) и значки на ней.

| Правило | Значение |
| --- | --- |
| Что ставится | устройства этой папки и её подпапки |
| Значок устройства | статус: онлайн / офлайн / консоль занята; клик — страница устройства, отдельная кнопка — консоль |
| Значок подпапки | худший статус всего, что внутри; клик — карта подпапки |
| Координаты | доли от размеров подложки (0…1): после замены картинки другого разрешения ничего не съезжает |
| Режимы | просмотр — для `view`; правка (перетаскивание, добавление, удаление значков, замена подложки) — для `folder.manage` |
| Навигация | масштаб колесом и щипком, сдвиг перетаскиванием, «вписать в экран» |
| Без подложки | значки на пустом поле |
| Не расставленные | список сбоку, перетаскиваются на карту |
| Без прав | значки устройств и папок, на которые нет `view`, не показываются |

Устройство в нескольких папках стоит на картах каждой из них, на каждой — со своими
координатами.

### Подложка

- PNG, JPEG или WebP, до 20 МБ и до 8000×8000 точек. **SVG не принимается**: в нём
  может быть скрипт.
- Тип определяется по содержимому файла, а не по расширению.
- Хранится в `BASTION_DATA_DIR/maps/<id папки>/<sha256>.<ext>`, в БД — путь и размеры.
  Отдаётся контроллером после проверки `view` с `X-Content-Type-Options: nosniff`.
- Без CDN: перетаскивание и масштаб — свой хук LiveView поверх `<img>` и значков,
  без сторонних библиотек.

## Контексты

| Контекст | Что меняется |
| --- | --- |
| `Bastion.Accounts` | `Admin` → `User`: несколько сотрудников, блокировка, смена и сброс пароля, сессии |
| `Bastion.Access` (новый) | `Role`, `Group`, `Grant`; `can?/3`, фильтры для запросов; события `GrantsChanged` |
| `Bastion.Fleet` | `Folder` с `parent_id` и `path`, устройство ↔ папки многие-ко-многим (`device_folders`) |
| `Bastion.Maps` (новый) | `Map` (подложка папки), `Placement` (значок: устройство или подпапка, x, y) |
| `Bastion.Console`, `Bastion.Control` | `actor` в API, проверка через `Access` |

`Access` не знает про устройства: `Fleet` отдаёт пути папок, `Access` сверяет их с
выдачами. `Maps` берёт статусы из `Fleet` и `Link`.

## Порядок работ

1. Сотрудники: `User`, вход, смена и сброс пароля, блокировка, журнал доступа (все — суперадмины)
2. Дерево папок и устройство в нескольких папках
3. Роли, группы, выдачи, проверка прав во всех контекстах, интерфейс управления
4. Консоль только для чтения
5. Карты папок

Каждый пункт — отдельная ветка и PR. Карты зависят только от дерева: пункт 5 можно
делать параллельно с 3–4.

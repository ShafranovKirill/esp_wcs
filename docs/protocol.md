# WCS Link — протокол ESP ↔ бастион, версия 1

Протокол связи устройства ESP WCS с бастионом. Цели: безопасность (mTLS, взаимная
сверка кодов при первом подключении), минимум накладных расходов на данные консоли,
быстрое восстановление после обрыва Wi-Fi.

Соединение всегда устанавливает ESP (исходящее, NAT не мешает).

## Транспорт

| Параметр | Значение |
| --- | --- |
| Адрес | `wss://<бастион>:7443/link` (порт по умолчанию — `CONFIG_WCS_BASTION_DEFAULT_PORT`) |
| TLS | только 1.3, ключи ECDSA P-256, только `TLS_AES_128_GCM_SHA256` / `TLS_CHACHA20_POLY1305_SHA256` |
| Сертификат клиента | необязателен: без него — сеанс **регистрации**, с ним — сеанс **устройства** |
| Быстрое переподключение | TLS 1.3 session tickets: после обрыва — без полного рукопожатия |
| Кадры WebSocket | текстовые — управляющие сообщения (JSON), бинарные — данные консоли |
| Максимальный кадр | 4 КиБ (текстовый и бинарный). Больше — закрытие с кодом 4002 |

## Доверие и коды

**Код** — короткий отпечаток открытого ключа для сверки человеком:
SHA-256 от `SubjectPublicKeyInfo` (DER), первые 10 байт, 20 hex-символов
заглавными, группами по 4: `7F3A-91C2-B4E0-5D17-C806`. 80 бит: код бастиона не меняется
годами и виден на главной странице, поэтому подбор ключа под него можно вести заранее,
офлайн. 48 бит для этого мало (дни на GPU), 80 бит — недостижимо.

- **Код бастиона** — от ключа корневого сертификата бастиона. Показывается на главной
  странице бастиона и в мастере настройки ESP (шаг «Бастион», после «Проверить»).
- **Код устройства** — от ключа устройства. Показывается в мастере ESP (шаг «Итог»)
  и в заявке на бастионе.

### Первое подключение (в мастере настройки ESP)

1. ESP генерирует ключ ECDSA P-256 (если его ещё нет). Закрытый ключ не покидает устройство.
2. «Проверить»: ESP подключается к бастиону **без проверки** сертификата, берёт из
   цепочки корневой сертификат и показывает код бастиона.
3. Пользователь сверяет код с главной страницей бастиона и нажимает «Далее». ESP
   запоминает SHA-256 от `SubjectPublicKeyInfo` корневого сертификата (**pin**).
4. Дальше ESP принимает только цепочку, которая ведёт к корневому сертификату с этим
   ключом. Сертификат сервера бастион может перевыпускать (новый IP, имя) — ESP это не мешает.

Бастион, в свою очередь, одобряет заявку, только если код устройства в ней совпал с
показанным в мастере.

## Состояния устройства на бастионе

```
            заявка             одобрить
  (нет) ──────────────▶ pending ─────────▶ approved ──отозвать──▶ revoked ──удалить──▶ (нет)
                           │                                         │
                           └── отклонить: заявка удаляется ──▶ (нет)  └── новая заявка ──▶ pending
```

- Отклонённая заявка удаляется, устройство может подать новую.
- У устройства одновременно не больше одной заявки; повторная подача — не чаще раза в минуту.
- Заявку на рассмотрении нельзя заменить заявкой с другим ключом (ответ `rejected`): иначе
  чужой мог бы подменить ключ, пока администратор сверяет код. Если ключ устройства
  действительно сменился (сброс до заводских), администратор отклоняет старую заявку.
- Одобрение привязано к коду, который видел администратор: если заявка за это время
  изменилась, одобрение не проходит.
- Устройств не больше 100, заявок на рассмотрении одновременно — не больше 10. Сверх
  лимита — закрытие 4008.
- Отозванное устройство не проходит mTLS; ESP сама переходит к регистрации, новая
  заявка приходит на одобрение.
- Удалить можно только отозванное устройство.

## Сообщения

Каждое управляющее сообщение — JSON-объект с полем `t` (тип). Неизвестный тип или
неверная структура — закрытие с кодом 4000. Время — миллисекунды Unix (`ms`).

### Начало сеанса (оба вида)

ESP → бастион, первым сообщением, не позже 10 с после подключения:

```json
{"t": "hello", "v": 1, "device_id": "7c2c678c8580", "fw": "1.2.0", "caps": ["console", "credit"]}
```

| Поле | Значение |
| --- | --- |
| `v` | версия протокола. Бастион поддерживает 1; неизвестная — закрытие 4001 |
| `device_id` | базовый MAC, 12 hex строчными. В сеансе устройства должен совпадать с сертификатом |
| `fw` | версия прошивки |
| `caps` | что умеет прошивка; неизвестные флаги игнорируются |

Бастион → ESP:

```json
{"t": "welcome", "v": 1, "session": "enroll", "time": 1793035999122, "hb": 15}
```

`session` — `enroll` (нет сертификата клиента) или `device` (mTLS). `hb` — интервал
heartbeat в секундах. `time` — время бастиона (первая установка часов ESP).

### Сеанс регистрации

ESP → бастион:

```json
{"t": "enroll", "name": "esp-wcs-8581", "csr": "-----BEGIN CERTIFICATE REQUEST-----\n..."}
```

`name` — имя по умолчанию (на бастионе меняется). CSR подписан ключом устройства,
CN = `device_id`.

Бастион → ESP (сразу и при каждом изменении, сеанс остаётся открытым):

```json
{"t": "enroll_status", "status": "pending"}
{"t": "enroll_status", "status": "approved", "cert": "-----BEGIN CERTIFICATE-----\n..."}
{"t": "enroll_status", "status": "rejected"}
```

- `approved` — ESP сохраняет сертификат, закрывает сеанс и подключается заново с mTLS.
  Если ESP была офлайн в момент одобрения, при следующей заявке с тем же ключом
  бастион сразу отвечает `approved` с сертификатом.
- `rejected` — ESP закрывает сеанс и подаёт новую заявку не раньше чем через 60 с.

В сеансе регистрации допустимы только `hello` и `enroll`.

### Сеанс устройства

**Heartbeat** — ESP раз в `hb` секунд:

```json
{"t": "hb", "seq": 812, "ts": 4513220, "rtt": 23, "rssi": -61, "uptime": 86400, "heap": 301234}
```

| Поле | Значение |
| --- | --- |
| `seq` | номер, растёт на 1 |
| `ts` | часы ESP, мс с загрузки |
| `rtt` | время отклика предыдущего heartbeat, мс (бастион показывает в списке) |
| `rssi`, `uptime`, `heap` | уровень сигнала, время работы, свободная память |

Бастион → ESP, сразу:

```json
{"t": "hb_ack", "seq": 812, "ts": 4513220, "time": 1793035999122}
```

`ts` возвращается как есть: ESP считает `rtt = сейчас − ts` и поправляет часы:
`время = time + rtt / 2`. Нет heartbeat 45 с — бастион считает устройство офлайн и
закрывает соединение.

**Команды** — бастион → ESP, у каждой свой `id`:

```json
{"t": "cmd", "id": 42, "op": "console_config", "args": {"baud": 115200, "data_bits": 8, "parity": "none", "stop_bits": 1}}
```

ESP → бастион, ровно один ответ на каждую команду:

```json
{"t": "cmd_result", "id": 42, "ok": true}
{"t": "cmd_result", "id": 43, "ok": false, "error": "invalid_args"}
```

| `op` | `args` | Действие |
| --- | --- | --- |
| `console_config` | `baud`, `data_bits`, `parity`, `stop_bits` | параметры консольного порта |
| `console_break` | `ms` (по умолчанию 300) | сигнал BREAK |
| `wifi_config` | `ssid`, `password` | сохранить новую сеть Wi-Fi и перезагрузиться после ответа (бастион предупреждает о риске) |
| `reboot` | — | перезагрузка после отправки ответа |
| `revoke` | — | стереть сертификат и перейти к регистрации |

Отзыв с бастиона идёт не командой, а закрытием 4003: запись в БД — источник истины,
сеанс закрывается сразу, а ESP при 4003 сама стирает сертификат и подаёт новую заявку.
Команда `revoke` прошивкой поддерживается и оставлена для ручной отладки.

Неизвестный `op` — ответ `{"ok": false, "error": "unknown_op"}`, неверные аргументы —
`invalid_args`, ошибка выполнения — `failed`. После успешного `console_config` ESP
сразу шлёт `status` с новыми параметрами.

Нет ответа за 10 с — бастион считает команду невыполненной. Не больше 10 команд в
секунду, иначе закрытие 4008.

**Статус** — ESP → бастион после `welcome` и при изменении (без ответа):

```json
{"t": "status", "console": {"baud": 9600, "data_bits": 8, "parity": "none", "stop_bits": 1}, "ip": "192.168.1.37"}
```

### Данные консоли

Бинарные кадры; первый байт — канал, дальше сырые байты.

| Байт 0 | Направление | Содержимое |
| --- | --- | --- |
| `0x01` | ESP → бастион | вывод консоли (из UART) |
| `0x02` | бастион → ESP | ввод в консоль (в UART) |

**Окно ввода.** Бастион отправляет ввод только в пределах кредита, выданного ESP,
чтобы на медленном порту (9600 бод) ничего не терялось:

```json
{"t": "credit", "bytes": 2048}
```

ESP выдаёт начальный кредит (2048 байт) после `welcome` и возвращает его по мере
передачи в UART (сообщением `credit`, когда набралось не меньше 512 байт). Ввод сверх
кредита — закрытие 4002. Без флага `credit` в `caps` бастион шлёт не больше 256 байт за раз.
Бастион держит до 16 КиБ ввода в очереди на устройство, лишнее отбрасывается.

**Вывод при обрыве.** ESP копит вывод консоли в буфере 16 КиБ (PSRAM), пока связи нет,
и отправляет его после следующего `welcome`. Бастион хранит последние 64 КиБ вывода
каждого подключённого устройства и показывает их тому, кто открыл консоль.

## Закрытие соединения

| Код | Причина |
| --- | --- |
| 1000 | обычное закрытие |
| 4000 | нарушение протокола: неизвестный тип, неверный JSON |
| 4001 | версия протокола не поддерживается |
| 4002 | слишком большой кадр или ввод сверх кредита |
| 4003 | доступ запрещён: устройство отозвано, `device_id` не совпадает с сертификатом |
| 4004 | нет `hello` за 10 с |
| 4005 | нет heartbeat 45 с |
| 4008 | слишком много команд или заявок |

## Переподключение

ESP переподключается бесконечно с паузой 1 с, удваивая до 60 с, со случайным
отклонением ±20 % (чтобы много устройств не ломились разом после сбоя). Успешный
`welcome` сбрасывает паузу. Пока связи нет, светодиод горит красным (`docs/led.md`).

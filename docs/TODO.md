## Материал для security.md (собрано из кода)

### ESP
- Пароль администратора: PBKDF2-HMAC-SHA256, соль 16 байт (os.urandom при сборке), хэш 32 байта, 10 000 итераций (`WCS_PBKDF2_ITERATIONS`, 1000–1000000), генерирует `wcs_defaults/gen_defaults.py` из `firmware/.env`; в прошивке только хэш. Проверка через PSA, сравнение за постоянное время (`ct_equal`), производный ключ затирается
- Сессии: токен 64 hex = 256 бит из `esp_fill_random` (аппаратный ГСЧ), до 4 сессий (вытесняется самая старая), простой 30 мин, сравнение за постоянное время; cookie `Secure; HttpOnly; SameSite=Strict`
- Перебор: 5 попыток бесплатно, затем пауза 5 с с удвоением до 900 с; блокировка общая на устройство (не по IP)
- Заголовки: CSP (`default-src 'self'; connect-src 'self' wss://<host>; frame-ancestors 'none'`), `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy: no-referrer`, `Cache-Control: no-store`
- WebSocket: `Origin` должен быть `https://192.168.4.1`, вход проверяется до рукопожатия (`ws_pre_handshake_cb`); защита от CSWSH
- Маршруты по уровню доступа, проверка в одном месте (`dispatch`); в рабочих режимах страниц настройки нет вообще
- HTTPS: ECDSA P-256, самоподписанный до 2099, создаётся на устройстве (`wcs_tls`, NVS), переживает сброс; порт 80 только перенаправляет. mbedTLS: включены TLS 1.2 и 1.3
- Wi-Fi AP: `WPA2_WPA3_PSK`, PMF capable (не required — возможен откат до WPA2), максимум 1 клиент, таймер 10 мин
- Хранение: настройки, пароли Wi-Fi, ключ устройства, HTTPS-ключ — NVS открытым текстом до Flash/NVS Encryption (этап 3). JTAG через USB включён
- `CONFIG_ESP_SYSTEM_MEMPROT_PMS` включена; Secure Boot не включён
- Заводские пароли одинаковы для всех плат, собранных с одним `.env`

### WCS Link
- TLS 1.3 только (бастион), шифры `TLS_AES_128_GCM_SHA256` / `TLS_CHACHA20_POLY1305_SHA256`, stateless session tickets
- Первое подключение: проверка без верификации → корневой сертификат из цепочки → код = первые 10 байт SHA-256(SPKI) (80 бит) → человек сверяет с главной бастиона → ESP сохраняет PEM корня и использует его как единственный якорь; проверка CN отключена (IP меняется)
- Регистрация: ключ ECDSA P-256 генерируется на ESP (PSA), CSR с CN = MAC; бастион одобряет только при совпадении кода устройства, одобрение привязано к коду; одна заявка, не чаще раза в минуту, ≤10 заявок, ≤100 устройств; сертификат 10 лет
- mTLS: сертификат клиента необязателен (без него — только регистрация); при каждом подключении CN и серийный номер сверяются с БД — отзыв без CRL; закрытие 4003 → ESP стирает сертификат
- Ограничения: кадр ≤4 КиБ, hello ≤10 с, heartbeat 15 с / офлайн 45 с, ≤10 команд/с, ввод только в пределах кредита, очередь ввода ≤16 КиБ
- Пароль Wi-Fi передаётся только внутри mTLS, в журнал не пишется

### Бастион
- Пароль администратора: Argon2 (`argon2_elixir`), `no_user_verify` против определения логина по времени, политика ≥12 символов и не из заглушек
- Перебор: по IP, 5 попыток, пауза 5 с ×2 до 15 мин
- Сессии: токен 32 байта, в БД только SHA-256, простой 30 мин, открытая консоль продлевает; cookie `Secure; HttpOnly; SameSite=Strict`, подписана и зашифрована
- CSP `default-src 'self'; script-src 'self'; ... frame-ancestors 'none'; form-action 'self'`, без inline-скриптов и CDN; `force_ssl` (HSTS) в prod; CSRF-токены Phoenix/LiveView
- CA: ECDSA P-256 на 20 лет, `ca.key` с правами 600, AES-256-GCM, ключ из `BASTION_CA_PASSPHRASE` через PBKDF2-HMAC-SHA256 600 000 итераций, соль 16, IV 12; в БД ключа нет
- Сертификат сервера переиздаётся сам при смене адресов
- Консоль: один владелец (процесс LiveView под монитором), вывод — только владельцу, история 64 КиБ в памяти сеанса (может содержать секреты из конфигов)
- Границы DDD проверяет `boundary` при компиляции
- mDNS: подмену `bastion.local` в LAN отсекает закреплённый корень (ESP) и проверка сертификата браузером; разбор пакетов встроенного ответчика ограничен (глубина, петли указателей)
- `/ca` без входа: только открытый ключ, сверка по отпечатку и коду
- Релиз работает от `nobody`, порты 443/80 через `cap_net_bind_service`; секреты (`.env`, `data/`) не в git и не в Docker-контексте

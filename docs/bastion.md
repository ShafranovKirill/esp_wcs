# Бастион

Сервер, к которому подключаются устройства ESP WCS в режиме Bastion connection:
регистрация и одобрение устройств, свой центр сертификации, mTLS, веб-терминал.
Требования — [`tz.md`](tz.md), раздел «Этап 2». Протокол с устройствами —
[`protocol.md`](protocol.md).

## Стек

| Что | Решение |
| --- | --- |
| Язык | Elixir 1.20 / Erlang OTP 28 (`bastion/.tool-versions`) |
| Веб | Phoenix 1.8, LiveView, Tailwind + daisyUI (светлая и тёмная темы по системе) |
| Языки интерфейса | русский и английский, gettext |
| БД | PostgreSQL 17 в Docker Compose |
| Терминал | xterm.js в бандле (esbuild), без CDN |
| Пароли | Argon2 |
| Границы контекстов | библиотека `boundary`: нарушение — ошибка компиляции |

## Порты

| Порт | Для кого | TLS |
| --- | --- | --- |
| 443 | администратор, браузер | HTTPS, сертификат сервера от своего CA |
| 7443 | устройства, WCS Link | TLS 1.3, сертификат клиента необязателен (без него — только регистрация) |

## Архитектура (DDD)

Шесть ограниченных контекстов. Каждый — модуль верхнего уровня с публичным API;
внутрь чужого контекста не обращаемся (проверяет `boundary`). Контексты общаются
вызовами публичного API и доменными событиями через `Phoenix.PubSub`.

| Контекст | Отвечает за | Агрегаты, сущности |
| --- | --- | --- |
| `Bastion.Accounts` | вход администратора, сессии | `Admin` |
| `Bastion.PKI` | свой центр сертификации: корневой сертификат, сертификат сервера, подпись CSR, коды | `CertificateAuthority` |
| `Bastion.Fleet` | устройства и папки: заявки, одобрение, отзыв, имена, журнал | `Device`, `Folder`, `DeviceEvent` |
| `Bastion.Link` | живые соединения WCS Link: процесс на устройство, heartbeat, онлайн/офлайн | `Session` (процесс) |
| `Bastion.Console` | консоль: блокировка «Устройство занято», поток данных, BREAK | `ConsoleLock` |
| `Bastion.Control` | команды устройству: настройки порта, Wi-Fi, перезагрузка | `Command` |

Интерфейсы — отдельно: `BastionWeb` (браузер администратора) и `BastionLink`
(эндпоинт устройств на 7443).

Внутри контекста — слои:

```
lib/bastion/fleet/
  fleet.ex              публичный API контекста (единственное, что видят снаружи)
  domain/               чистые структуры и правила, без Ecto и Phoenix
  application/          сценарии: approve_request, revoke_device, move_to_folder…
  infrastructure/       Ecto-схемы и репозитории, внешние библиотеки
```

Доменные правила (переходы состояний устройства, проверка имени) живут в `domain/`
и тестируются без БД.

## Устройство

Состояния — [`protocol.md`](protocol.md#состояния-устройства-на-бастионе).

| Правило | Значение |
| --- | --- |
| ID | базовый MAC, 12 hex (`7c2c678c8580`), не меняется |
| Имя | 1–64 символа, уникально без учёта регистра; по умолчанию от устройства (`esp-wcs-8581`) |
| Папка | одна или «Без папки»; папки в один уровень |
| Заявка | одна на устройство, повторная — не чаще раза в минуту; отклонённая удаляется; заменить ключ в заявке на рассмотрении нельзя |
| Отзыв | устройство остаётся в списке с пометкой, журнал сохраняется |
| Удаление | только отозванного; удаляется вместе с журналом |
| Онлайн | heartbeat раз в 15 с, офлайн после 45 с тишины |
| Устройств | до 100, заявок на рассмотрении — до 10 |

Журнал устройства (`DeviceEvent`): заявка, одобрение, подключение и отключение,
переименование, перенос в папку, захват и освобождение консоли, команды, отзыв.

## Центр сертификации

- При первом запуске создаётся корневой сертификат (ECDSA P-256, 20 лет).
  Закрытый ключ — файл `ca.key` с правами 600 в каталоге данных, зашифрован паролем
  `BASTION_CA_PASSPHRASE`. В БД ключ не хранится.
- Сертификат сервера подписывается корневым. В нём: `bastion.local`, имя машины,
  все её IP и `BASTION_HOSTS`. При запуске бастион сверяет список и, если он
  изменился, перевыпускает сертификат сам.
- Сертификаты устройств: подпись CSR при одобрении, срок 10 лет, CN = ID устройства.
  Отзыв проверяется по БД при каждом подключении — списки отзыва не нужны.
- **Код бастиона** (`7F3A-91C2-B4E0-5D17-C806`) — на главной странице, для сверки при настройке ESP.

Потеря `ca.key` или пароля = все устройства нужно регистрировать заново.

## Администратор

Один. Логин и пароль — в `bastion/.env`, в БД попадает только хэш:

```
mix bastion.admin            # создать, если нет; существующего не меняет
mix bastion.admin --reset    # перезаписать пароль из .env
```

В релизе то же: `bin/bastion eval "Bastion.Release.admin()"` / `"Bastion.Release.admin(reset: true)"`.

Пароль — не короче 12 символов и не из шаблона. В разработке (`config/dev.exs`,
`weak_admin_password`) проверка снята, чтобы работал `admin / admin` из `.env.example`.

Сессия заканчивается после 30 минут бездействия; открытая консоль считается
активностью. После 5 неверных паролей — нарастающая пауза.

## Тестовое устройство

Для ручной отладки бастиона без ESP — `mix bastion.device`: настоящий клиент WCS Link
по сети (TLS 1.3, mTLS), ведёт себя как прошивка:

```
mix bastion.device                       # новое устройство со случайным ID
mix bastion.device --id 7c2c678c8580     # то же устройство ещё раз (ключ и сертификат сохранены)
mix bastion.device --host 192.168.1.10 --port 7443 --name lab-1
```

- При первом запуске показывает код бастиона и спрашивает, совпадает ли он с главной
  страницей, — так же, как мастер ESP; корень закрепляется в `data/devices/<id>/bastion.pem`.
- Ключ устройства (`key.pem`) и сертификат (`cert.pem`) — там же; код устройства
  печатается при запуске, его видно в заявке.
- Консоль — петля, как перемычка GPIO17↔GPIO18 на плате: ввод возвращается выводом.
  Кредит выдаётся и возвращается как на ESP.
- Команды: `console_config` (с проверкой и `status`), `console_break` (в вывод —
  `[BREAK 300 ms]`), `wifi_config` и `reboot` (переподключение), `revoke`. Закрытие
  4003 — стирает сертификат и через 60 с подаёт новую заявку.
- Два запуска с одним `--id` вытесняют друг друга — так же ведёт себя бастион с двумя ESP
  с одинаковым ключом.

Для автотестов — `test/support/fake_device.ex`: без сети, сеанс вызывается напрямую.

## Консоль

Управляет одна вкладка браузера. В остальных — «Устройство занято» с кнопкой
«Забрать» (с подтверждением): зависшая вкладка не блокирует консоль.

Как устроено (`Bastion.Console`):

- **Блокировка** — процесс `Console.Application.Locks` и ETS-таблица «устройство →
  процесс-владелец». Владелец — процесс LiveView вкладки; он под монитором, поэтому
  закрытая вкладка или оборванный браузер освобождают консоль сами. Блокировка не
  зависит от связи с устройством: при обрыве Wi-Fi вкладка остаётся владельцем.
- **Данные** — сеанс WCS Link публикует вывод в тему `console:<id>`; подписан на неё
  только владелец (подписка снимается, когда консоль забрали). Ввод принимается
  только от владельца и уходит в сеанс устройства с учётом кредита.
- **История** — сеанс хранит последние 64 КиБ вывода; при открытии консоли она
  выводится в терминал.
- **BREAK** — только владельцу; параметры порта может менять любой открытый сеанс
  администратора. Параметры проверяются до отправки (`Console.Domain.Line`).
- **Журнал** — захват и освобождение консоли, BREAK и смена параметров порта.
- Открытая консоль раз в минуту продлевает сессию администратора.

## Интерфейс

- **Главная.** Код бастиона, заявки на одобрение (с кодом устройства), устройства по
  папкам: статус, отклик, сигнал. Поиск. Клик по устройству — его страница.
- **«Как подключить».** Пошаговая инструкция и текущие адреса бастиона
  (`bastion.local:7443`, IP, домен) с кнопкой «Копировать».
- **Страница устройства**, вкладки:
  - **Консоль** — xterm.js, скорость порта, BREAK, «Забрать консоль»;
  - **Настройки** — имя, папка, консольный порт, Wi-Fi; «Опасные действия»:
    перезагрузка, отзыв, удаление;
  - **Сведения** — ID, IP, прошивка, время работы, сигнал, код, срок сертификата;
  - **Журнал** — события устройства.

## Управление устройством

`Bastion.Control` — команды устройству поверх `Link.command/3` (ответ ждём до 10 с,
не больше 10 команд в секунду на устройство):

| Действие | Команда | Что видит администратор |
| --- | --- | --- |
| Параметры порта | `console_config` | вкладки «Консоль» и «Настройки», сразу после ответа |
| Сеть Wi-Fi | `wifi_config` | предупреждение и подтверждение; устройство сохраняет сеть и перезагружается |
| Перезагрузка | `reboot` | подтверждение |
| Отзыв | закрытие 4003 | подтверждение; устройство стирает сертификат |

Аргументы проверяются до отправки (`Control.Domain.Wifi`: SSID 1–32 байта, пароль
пустой или 8–63). В журнал пишется команда и SSID, пароль — никогда.

## mDNS

Контекст `Bastion.Discovery` объявляет `bastion.local` (A-записи всех рабочих IPv4 машины;
мосты Docker, `veth`, VPN-туннели и point-to-point интерфейсы пропускаются). Способ
выбирается переменной `BASTION_MDNS`:

| Значение | Способ |
| --- | --- |
| `auto` (по умолчанию) | Linux с работающим Avahi — `avahi-publish -a -R`; macOS — `dns-sd -P`; иначе встроенный ответчик |
| `avahi`, `dns_sd`, `builtin` | принудительно этот способ |
| `off` | не объявлять |

- **Avahi / dns-sd** — по процессу на адрес под присмотром `Discovery.Infrastructure.Publisher`;
  раз в минуту список адресов сверяется, при изменении процессы перезапускаются. Каждый
  процесс запущен через обёртку `sh`: когда BEAM завершается, закрытый stdin убивает
  дочерний процесс — «осиротевших» объявлений не остаётся.
- **Встроенный ответчик** (`Discovery.Infrastructure.Responder`) — UDP 5353, группа
  224.0.0.251, отвечает только на A/ANY-запросы своего имени. Разбор пакета —
  `Discovery.Domain.Dns`: ограничение глубины меток и защита от петель указателей сжатия.
  Запрос с порта, отличного от 5353 (legacy unicast), получает ответ на адрес отправителя
  с тем же `id`. Работает и рядом с Avahi (порт открыт с `reuseaddr`).
- Проверено на Fedora: `avahi-resolve -4 -n bastion.local` и `getent ahostsv4 bastion.local`
  (через nss-mdns) в режимах `avahi` и `builtin`.

Если mDNS в сети не работает, в мастере ESP вводится IP — он есть на странице «Как подключить».

## Корневой сертификат

Страница `/ca` открыта без входа (ссылка — со страницы входа и «Как подключить»): кнопка
скачивания `esp-wcs-bastion-ca.crt`, код бастиона, отпечаток SHA-256 и инструкции для
Windows, macOS, Linux (Fedora/RHEL, Debian/Ubuntu, Chrome), Firefox, Android и iOS.
Сам файл — `/ca.crt`. Отдавать корневой сертификат без входа безопасно: в нём только
открытый ключ, а подлинность сверяется по отпечатку и коду бастиона.

## Запуск

PostgreSQL — всегда в Docker Compose. Бастион:

- **разработка, ноутбук** — напрямую (`mix phx.server`), в Docker только БД;
- **сервер на Linux** — в Docker Compose с `network_mode: host` (бастиону нужны
  настоящие IP машины для сертификата и mDNS): `docker compose --profile server up -d --build`.
  Релиз работает от `nobody`; привилегированные порты 443/80 — через
  `cap_net_bind_service` только для BEAM.

Подробности — `bastion/README.md`.

| --- | --- |

| `SECRET_KEY_BASE` | ключ подписи cookie Phoenix |

# Установка среды и сборка

## ESP-IDF

Используется **ESP-IDF v6.1**, установлен в `~/esp/esp-idf`.

```sh
mkdir -p ~/esp && cd ~/esp
git clone -b v6.1 --recursive https://github.com/espressif/esp-idf.git
cd esp-idf && ./install.sh esp32s3
```

Активация окружения в каждом новом терминале (удобно завести алиас):

```sh
alias get_idf='. $HOME/esp/esp-idf/export.sh'
get_idf
```

## Доступ к порту (Linux)

Плата видна как `/dev/ttyACM0` (мост WCH CH343, драйвер `cdc_acm`).
Пользователь должен быть в группе `dialout`:

```sh
sudo usermod -aG dialout $USER   # затем перелогиниться
```

## Заводские настройки и пароли (`firmware/.env`)

Логин и пароль администратора, имя и пароль Wi-Fi точки настройки задаются
в `firmware/.env`. Файл в git не попадает; шаблон — `firmware/.env.example`.

```sh
cd firmware
cp .env.example .env   # если .env нет, сборка создаст его сама с заводскими значениями
$EDITOR .env
idf.py build           # значения перегенерируются автоматически
```

| Переменная | По умолчанию | Ограничения |
| --- | --- | --- |
| `WCS_SETUP_AP_SSID_PREFIX` | `ESP-WCS-` | до 28 символов; к нему добавляются 4 hex-цифры MAC |
| `WCS_SETUP_AP_PASSWORD` | `adminadmin` | 8–63 символа (WPA2) |
| `WCS_DIRECT_AP_SSID_PREFIX` | `ESP-WCS-DIRECT-` | до 28 символов; к нему добавляются 4 hex-цифры MAC |
| `WCS_DIRECT_AP_PASSWORD` | `adminadmin` | 8–63 символа (WPA2) |
| `WCS_ADMIN_USERNAME` | `admin` | до 32 символов |
| `WCS_ADMIN_PASSWORD` | `admin` | до 64 символов |
| `WCS_PBKDF2_ITERATIONS` | `10000` | 1000–1000000 |

Пароль администратора в прошивку попадает только хэшем PBKDF2-HMAC-SHA256
со случайной солью (`components/wcs_defaults/gen_defaults.py`). Пароль Wi-Fi
хранится как есть: точке доступа он нужен в открытом виде (защитит Flash
Encryption на этапе 3). Допустимы только печатные ASCII-символы.
Переменные, которых нет в `.env`, берутся из `.env.example` — после обновления
прошивки старый `.env` продолжает работать.

## Сборка и прошивка

```sh
cd firmware
idf.py set-target esp32s3        # один раз, и после удаления sdkconfig
idf.py build
idf.py -p /dev/ttyACM0 flash
idf.py -p /dev/ttyACM0 monitor   # выход: Ctrl+]
```

Если `sdkconfig` удалён, обязательно заново `idf.py set-target esp32s3` —
иначе сборка пойдёт под обычный ESP32.

## Настройка устройства

1. Удерживать **BOOT** 5 секунд (уже после загрузки, не при подаче питания) и отпустить.
   Светодиод при удержании мигает синим, после отпускания синий «дышит».
2. Подключиться к Wi-Fi `ESP-WCS-XXXX` (XXXX — конец MAC), пароль из `.env`.
3. Открыть в браузере `192.168.4.1` — откроется `https://192.168.4.1/` (с `http://`
   перенаправляет автоматически). Сертификат самоподписанный, поэтому браузер один раз
   предупредит «Подключение не защищено»: «Дополнительно» → «Перейти на сайт».
   Шифрование при этом полноценное. Автоматического окна входа (captive portal)
   нет сознательно: Android/Samsung его не показывали, а с самоподписанным HTTPS оно бесполезно.
4. Войти логином и паролем администратора.
5. Выбрать режим работы (подсказка — кнопка «?» рядом с режимом):
   - **Direct connection** — страница покажет новую точку доступа
     `ESP-WCS-DIRECT-XXXX`, её пароль и адрес. После «Применить» точка настройки
     закрывается, поднимается точка Direct; на ней после входа открывается консоль.
   - **Bastion connection** — выбрать Wi-Fi сеть из найденных, ввести пароль,
     «Подключиться». Устройство подключается к сети, не закрывая точку настройки
     (на время смены канала связь со страницей может прерваться на несколько секунд).
     Затем ввести адрес бастиона (IP, домен или `bastion.local`, можно с портом)
     и «Применить».

Режим сохраняется в NVS и восстанавливается после перезагрузки. В Direct после
перезагрузки точка доступа выключена — короткое нажатие кнопки поднимает её.
Удержание 15 секунд — сброс до заводских настроек и перезагрузка.
Три быстрых нажатия (пауза между ними не больше 0,5 с) — сразу режим Direct
с поднятой точкой доступа, без захода в веб-интерфейс настройки. Работает из
любого состояния; сохранённые сеть и адрес бастиона не стираются.

Точка доступа (и настройки, и Direct) выключается, если к ней 10 минут никто не
подключён; отсчёт начинается заново после отключения последнего клиента. Настройка
по таймауту закрывается без сохранения — устройство возвращается в прежний режим.

Пока веб-интерфейс работает по HTTP; HTTPS — пункт 3 этапа 1.

## CI

GitHub Actions (`.github/workflows/firmware.yml`) собирает прошивку на каждый
PR и push в `main`, если менялось что-то в `firmware/`. Готовые `.bin`
выкладываются как артефакты сборки.

## HTTPS и сертификат устройства

Веб-интерфейс работает только по HTTPS (порт 443). На порту 80 — лишь перенаправление
на HTTPS: страницы, пароли и cookie по нему не передаются (cookie сессии с флагом `Secure`).

Ключ ECDSA P-256 и самоподписанный сертификат создаются на устройстве при первом
запуске (~0,3 с), срок — до 2099 года. В сертификате: адрес `192.168.4.1` и имя
`esp-wcs-XXXX.local` (XXXX — конец MAC точки доступа). Хранятся в NVS, в пространстве
`wcs_tls`, отдельно от настроек: **сброс до заводских их не стирает**, поэтому браузер,
уже принявший сертификат, не будет предупреждать заново. Новый сертификат появится
только после полной очистки флеша (`idf.py erase-flash`).

В логе при загрузке:

```
wcs_tls: no valid certificate for esp-wcs-XXXX|192.168.4.1, generating   ← первый запуск
wcs_tls: certificate loaded for esp-wcs-XXXX|192.168.4.1                   ← дальше
```

Пока браузер показывает предупреждение, в логе будут ошибки — это браузер
обрывает соединение, не доверяя сертификату; после «Перейти на сайт» они прекращаются:

```
E esp-tls-mbedtls: mbedtls_ssl_handshake returned -0x7780
```

**Страница бесконечно грузится на телефоне** — почти всегда мобильный интернет:
телефон видит, что в сети точки доступа нет интернета, и шлёт запросы через мобильные
данные. Выключить мобильные данные или на вопрос «Сеть без доступа к интернету»
ответить «Оставаться подключённым». Признак в логе — нет ни одной строки
`esp_https_server: performing session handshake`.

Убрать предупреждение браузера совсем можно будет на этапе 3: бастион выдаст
устройству сертификат от своего корневого (`docs/roadmap.md`).

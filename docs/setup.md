# Установка среды и сборка

## ESP-IDF

Используется **ESP-IDF v6.1**, установлен в `~/esp/esp-idf`.

```sh
mkdir -p ~/esp && cd ~/esp
git clone -b v6.1 --recursive https://github.com/espressif/esp-idf.git
cd esp-idf && ./install.sh esp32s3
```

Активация окружения в каждом новом терминале (удобно завести алиас):

```sh
alias get_idf='. $HOME/esp/esp-idf/export.sh'
get_idf
```

## Доступ к порту (Linux)

Плата видна как `/dev/ttyACM0` (мост WCH CH343, драйвер `cdc_acm`).
Пользователь должен быть в группе `dialout`:

```sh
sudo usermod -aG dialout $USER   # затем перелогиниться
```

## Заводские настройки и пароли (`firmware/.env`)

Логин и пароль администратора, имя и пароль Wi-Fi точки настройки задаются
в `firmware/.env`. Файл в git не попадает; шаблон — `firmware/.env.example`.

```sh
cd firmware
cp .env.example .env   # если .env нет, сборка создаст его сама с заводскими значениями
$EDITOR .env
idf.py build           # значения перегенерируются автоматически
```

| Переменная | По умолчанию | Ограничения |
| --- | --- | --- |
| `WCS_SETUP_AP_SSID_PREFIX` | `ESP-WCS-` | до 28 символов; к нему добавляются 4 hex-цифры MAC |
| `WCS_SETUP_AP_PASSWORD` | `adminadmin` | 8–63 символа (WPA2) |
| `WCS_DIRECT_AP_SSID_PREFIX` | `ESP-WCS-DIRECT-` | до 28 символов; к нему добавляются 4 hex-цифры MAC |
| `WCS_DIRECT_AP_PASSWORD` | `adminadmin` | 8–63 символа (WPA2) |
| `WCS_ADMIN_USERNAME` | `admin` | до 32 символов |
| `WCS_ADMIN_PASSWORD` | `admin` | до 64 символов |
| `WCS_PBKDF2_ITERATIONS` | `10000` | 1000–1000000 |

Пароль администратора в прошивку попадает только хэшем PBKDF2-HMAC-SHA256
со случайной солью (`components/wcs_defaults/gen_defaults.py`). Пароль Wi-Fi
хранится как есть: точке доступа он нужен в открытом виде (защитит Flash
Encryption на этапе 3). Допустимы только печатные ASCII-символы.
Переменные, которых нет в `.env`, берутся из `.env.example` — после обновления
прошивки старый `.env` продолжает работать.

## Сборка и прошивка

```sh
cd firmware
idf.py set-target esp32s3        # один раз, и после удаления sdkconfig
idf.py build
idf.py -p /dev/ttyACM0 flash
idf.py -p /dev/ttyACM0 monitor   # выход: Ctrl+]
```

Если `sdkconfig` удалён, обязательно заново `idf.py set-target esp32s3` —
иначе сборка пойдёт под обычный ESP32.

## Настройка устройства

1. Удерживать **BOOT** 5 секунд (уже после загрузки, не при подаче питания) и отпустить.
   Светодиод при удержании мигает синим, после отпускания синий «дышит».
2. Подключиться к Wi-Fi `ESP-WCS-XXXX` (XXXX — конец MAC), пароль из `.env`.
3. Открыть в браузере `192.168.4.1` — откроется `https://192.168.4.1/` (с `http://`
   перенаправляет автоматически). Сертификат самоподписанный, поэтому браузер один раз
   предупредит «Подключение не защищено»: «Дополнительно» → «Перейти на сайт».
   Шифрование при этом полноценное. Автоматического окна входа (captive portal)
   нет сознательно: Android/Samsung его не показывали, а с самоподписанным HTTPS оно бесполезно.
4. Войти логином и паролем администратора.
5. Выбрать режим работы (подсказка — кнопка «?» рядом с режимом):
   - **Direct connection** — страница покажет новую точку доступа
     `ESP-WCS-DIRECT-XXXX`, её пароль и адрес. После «Применить» точка настройки
     закрывается, поднимается точка Direct; на ней после входа открывается консоль.
   - **Bastion connection** — выбрать Wi-Fi сеть из найденных, ввести пароль,
     «Подключиться». Устройство подключается к сети, не закрывая точку настройки
     (на время смены канала связь со страницей может прерваться на несколько секунд).
     Затем ввести адрес бастиона (IP, домен или `bastion.local`, можно с портом;
     адреса — на странице бастиона «Как подключить») и «Проверить»: мастер покажет
     **код бастиона** — он должен совпасть с кодом на главной странице бастиона.
     На последнем шаге — **код устройства**; после «Применить» устройство пришлёт
     заявку, одобрите её на бастионе, сверив этот код.
     Светодиод: фиолетовый дышит — подключение, жёлтый дышит — ждёт одобрения,
     фиолетовый ровно — на связи, красный дышит — связь с бастионом потеряна.

Режим сохраняется в NVS и восстанавливается после перезагрузки. В Direct после
перезагрузки точка доступа выключена — короткое нажатие кнопки поднимает её.
Удержание 15 секунд — сброс до заводских настроек и перезагрузка.
Три быстрых нажатия (пауза между ними не больше 0,5 с) — сразу режим Direct
с поднятой точкой доступа, без захода в веб-интерфейс настройки. Работает из
любого состояния; сохранённые сеть и адрес бастиона не стираются.

Точка доступа (и настройки, и Direct) выключается, если к ней 10 минут никто не
подключён; отсчёт начинается заново после отключения последнего клиента. Настройка
по таймауту закрывается без сохранения — устройство возвращается в прежний режим.

Пока веб-интерфейс работает по HTTP; HTTPS — пункт 3 этапа 1.

## HTTPS и сертификат устройства

Веб-интерфейс работает только по HTTPS (порт 443). На порту 80 — лишь перенаправление
на HTTPS: страницы, пароли и cookie по нему не передаются (cookie сессии с флагом `Secure`).

Ключ ECDSA P-256 и самоподписанный сертификат создаются на устройстве при первом
запуске (~0,3 с), срок — до 2099 года. В сертификате: адрес `192.168.4.1` и имя
`esp-wcs-XXXX.local` (XXXX — конец MAC точки доступа). Хранятся в NVS, в пространстве
`wcs_tls`, отдельно от настроек: **сброс до заводских их не стирает**, поэтому браузер,
уже принявший сертификат, не будет предупреждать заново. Новый сертификат появится
только после полной очистки флеша (`idf.py erase-flash`).

В логе при загрузке:

```
wcs_tls: no valid certificate for esp-wcs-XXXX|192.168.4.1, generating   ← первый запуск
wcs_tls: certificate loaded for esp-wcs-XXXX|192.168.4.1                   ← дальше
```

Пока браузер показывает предупреждение, в логе будут ошибки — это браузер
обрывает соединение, не доверяя сертификату; после «Перейти на сайт» они прекращаются:

```
E esp-tls-mbedtls: mbedtls_ssl_handshake returned -0x7780
```

**Страница бесконечно грузится на телефоне** — почти всегда мобильный интернет:
телефон видит, что в сети точки доступа нет интернета, и шлёт запросы через мобильные
данные. Выключить мобильные данные или на вопрос «Сеть без доступа к интернету»
ответить «Оставаться подключённым». Признак в логе — нет ни одной строки
`esp_https_server: performing session handshake`.

Убрать предупреждение браузера совсем можно будет на этапе 3: бастион выдаст
устройству сертификат от своего корневого (`docs/roadmap.md`).

## Дальность Direct

В мастере Direct вводится примерная дальность на открытом пространстве: целое число
от 10 до 100 метров, по умолчанию 100. Это предварительная шкала мощности, а не
измеренный или гарантированный радиус. Стены, помехи и приёмник влияют на связь.
Значение сохраняется в NVS (`direct_range`); старые настройки без этого ключа используют 100 м.
Сброс до заводских возвращает значение по умолчанию. Точка настройки работает на полной мощности.

Шкала: `P = clamp(20 + 20·log10(дальность / 100), 2, 20)` dBm.
Например: 10 м → 2 dBm, 25 м → около 8 dBm, 50 м → около 14 dBm,
100 м → 20 dBm до округления драйвером. ESP-IDF применяет дискретные ступени
и ограничения PHY/страны; соседние значения метров могут давать одну мощность.
Опорные 100 м при 20 dBm требуют последующей калибровки на реальной плате.

## Точка доступа ноутбука

Linux с NetworkManager; бастион работает непосредственно на ноутбуке. Кнопка
управляет сетью хоста сервера, а не компьютера удалённого посетителя страницы.

1. В `bastion/.env` задать `BASTION_HOTSPOT_ENABLED=true`,
   `BASTION_HOTSPOT_SSID=ESP-WCS-BASTION`, `BASTION_HOTSPOT_PASSWORD=admin-admin`.
2. Из `bastion/` один раз выполнить `sudo scripts/setup-hotspot wlp2s0`, подставив
   имя физического Wi-Fi интерфейса. Скрипт создаёт systemd-службу виртуального
   интерфейса `wcsap0` и профиль NetworkManager `esp-wcs-bastion` (2,4 ГГц,
   WPA2, DHCP, адрес ноутбука `10.42.0.1/24`, без автозапуска сети).
   При активном firewalld разрешает WCS Link из `10.42.0.0/24` в зоне `nm-shared`.
3. Перезапустить бастион. Суперадминистратору на `/connect` доступны кнопки
   создания и выключения точки. NetworkManager должен разрешать пользователю
   бастиона управление системными подключениями; весь сервер от root не запускать.
   Пароль профиля меняется повторным запуском скрипта после правки `.env`.
4. В `firmware/.env` задать соответствующие `WCS_LAPTOP_SSID`,
   `WCS_LAPTOP_PASSWORD`, `WCS_LAPTOP_ADDR=10.42.0.1:7443` и
   `WCS_LAPTOP_CA_FILE=../bastion/data/ca.crt`. Это публичный сертификат CA,
   не закрытый ключ. Без него шесть нажатий ничего не переключают, в COM-логе — причина.
   Собрать и прошить устройство. Изменения файла CA учитываются при сборке.
5. Включить точку и нажать BOOT ровно шесть раз, пауза между нажатиями до 0,5 с.
   Действие выполняется после окончания серии. Плата подключается без мастера;
   новую заявку нужно подтвердить на бастионе после сверки кода устройства.

Подключение временное: сохранённые SSID, адрес и CA бастиона не перезаписываются.
Если за 120 с не получено соединение или состояние ожидания подтверждения,
плата возвращается в сохранённый режим (для Direct поднимает AP).
При перезагрузке также используется сохранённый режим. Ожидающая подтверждения
плата остаётся в режиме ноутбука. Три нажатия возвращают Direct, удержания
5/15 с работают как прежде. Другие серии коротких нажатий игнорируются.

Интернет для консоли не требуется. Совместный режим клиента Wi-Fi и AP зависит
от адаптера, драйвера и ограничений каналов; ESP32-S3 работает только на 2,4 ГГц.
На текущем ноутбуке оба интерфейса успешно включались одновременно. Для других
адаптеров может потребоваться отдельный USB Wi-Fi адаптер. Доступ из Docker
к NetworkManager этим вариантом не предусмотрен. Порт Link — 7443, а локальная
страница разработки остаётся на `https://localhost:4443`.

## Диагностика консольного порта

В Direct на `/console` раскрыть «Диагностика UART»: данные обновляются раз в 2 с.
В бастионе счётчики доступны на странице информации онлайн-устройства и
обновляются heartbeat. Счётчики общие с момента включения, не сбрасываются при
смене скорости. TX — байты, принятые драйвером UART, а не подтверждение их
получения коммутатором. RX — байты, прочитанные из драйвера. Ошибки — события,
полученные из очереди драйвера; это не анализатор всех электрических импульсов.
Уровень RX — моментальный снимок входа, он не определяет исправность RS-232.
Данные консоли и пароли в диагностику не записываются.

Для **Eltex ESR-12VF и MES2308R** заводские параметры: **115200, 8N1,
без аппаратного и программного управления потоком**, терминал VT100.
В ESP WCS по умолчанию 9600; выставить 115200 в консоли или настройках устройства,
затем нажать Enter. Ранее сохранённые параметры Eltex могут отличаться.
Источники: [руководство ESR](https://docs.eltex-co.ru/pages/viewpage.action?pageId=55183639),
[подключение MES23xx/33xx/35xx/5324](https://docs.eltex-co.ru/pages/viewpage.action?pageId=45452583).

- TX растёт, RX остаётся нулём: проверить именно порт Console устройства,
  питание MAX3232 от 3,3 В, общую землю и кабель. Отсутствие ошибок при нулевом RX
  не подтверждает правильную скорость. TXD/RXD наугад не переставлять.
- RX растёт, символы нечитаемые или растут ошибки кадра: сверить скорость/формат,
  качество соединения и соответствие распиновки конкретному устройству.
- Переполнения: часть вывода могла потеряться; проверить нагрузку и скорость.
- Для проверки ESP без MAX3232 и коммутатора при отключённой внешней линии
  замкнуть TX/RX консоли по схеме из `hardware/console-wiring.md`: ввод должен
  вернуться эхом. В рабочей консоли локальное эхо не включено, поэтому отсутствие
  отображения набираемого текста само по себе не означает отсутствие передачи.

Проверка распознавания нажатий без платы: `python3 firmware/tests/test_button.py`
из корня репозитория (нужен системный C-компилятор).

## Профили терминала и подбор скорости на бастионе

Рядом с параметрами порта на вкладке консоли находятся «Профили устройств»
и «Подобрать скорость». В каталоге Eltex есть семейства MES (MES2308R)
и ESR (ESR-12VF). Оба профиля задают 115200, 8N1, без управления потоком и
Backspace=BS (Ctrl+H). Для MES2308R стирание проверено на реальном устройстве;
для ESR это настраиваемое исходное значение, проверка на железе ещё нужна.
Выбор BS/DEL и название профиля сохраняются для каждой платы в localStorage
текущего браузера. Сами параметры UART сохраняются на ESP как прежде.
Профиль применяется только после успешного ответа устройства. Ручной выбор
Backspace не меняет UART. Ctrl+H продолжает работать независимо от выбора.

Подбор скорости доступен владельцу консоли с правом `device.configure`,
на прошивках с capability `console_probe`. Перебираются стандартные скорости,
формат фиксирован 8N1. Порт слушается около 1,6 с на каждой скорости после
паузы на переключение; анализируется только свежий вывод, не история.
Подбор пассивный: Enter, BREAK и команды не отправляются. На молчащем порту
результата не будет; нужен поток вывода от подключённого устройства.
Читаемый текст является эвристикой, а не доказательством скорости: результат
показывается вместе с образцом, для сохранения нужно «Применить скорость».

Команды `console_probe` временно меняют параметры без записи в NVS;
`console_probe_end` возвращает исходную линию. Отмена, ошибка и завершение
подбора возвращают исходные параметры. Плата также сама восстанавливает их
через 6 с без следующего шага; это работает и при закрытии вкладки или потере
связи. После захвата консоли другой вкладкой подбор прекращается, а временная
настройка возвращается по таймауту. Обычное применение параметров отменяет
временную настройку. Старая прошивка не поддерживает подбор и требует обновления.
